---
title: "Check eligibility"
api: "GET /v1/users/{id}/eligibility"
description: "Returns which instruments a user may buy and sell, with a reason for each refusal."
---

See [Eligibility](/concepts/eligibility) for how the result is decided and the full list of reason codes.

## Path parameters

<ParamField path="id" type="string" required>
  The user's id.
</ParamField>

## Query parameters

<ParamField query="instruments" type="string">
  Comma-separated instrument ids, such as `equity:NVDA,gold`. Leave out to check every instrument.
</ParamField>

## Returns

<ResponseField name="object" type="string">
  Always `eligibility`.
</ResponseField>
<ResponseField name="user_id" type="string">
  The user checked.
</ResponseField>
<ResponseField name="data" type="object[]">
  One entry per instrument.

  <Expandable title="properties" defaultOpen>
    <ResponseField name="instrument" type="string">
      The instrument id.
    </ResponseField>
    <ResponseField name="eligible" type="boolean">
      Whether the user can buy the instrument.
    </ResponseField>
    <ResponseField name="buy_allowed" type="boolean">
      Whether the user can buy.
    </ResponseField>
    <ResponseField name="sell_allowed" type="boolean">
      Whether the user can sell what they hold.
    </ResponseField>
    <ResponseField name="hold_only" type="boolean">
      `true` when the user can sell but not buy more.
    </ResponseField>
    <ResponseField name="reasons" type="object[]">
      Why buying or selling isn't allowed. Each has a `code` and `message`. Empty when eligible.
    </ResponseField>
    <ResponseField name="required_actions" type="string[]">
      Steps that would make the user eligible, when there are any.
    </ResponseField>
  </Expandable>
</ResponseField>
